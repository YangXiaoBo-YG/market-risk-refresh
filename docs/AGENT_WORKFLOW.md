# Agent 协作、数据核验与运营责任

本文件记录负责人采用的 Agent 辅助产品开发方式，并给出可复用的工作包。它与生产定时任务是两层流程：定时采集目前由脚本和 GitHub Actions 执行，不代表后台持续运行多个自主 Agent。具体一次核验是否执行，以任务证据记录为准。

## 分工与交付

| 角色 | 职责 | 必须交付 | 责任边界 |
|---|---|---|---|
| 负责人 / 主 Agent | 把研究问题拆成指标、来源、计算和页面任务，裁决冲突 | 需求、任务分工、验收结论 | 项目负责人作最终判断 |
| 来源调查 Agent | 比较官方资料与可访问的数据页面 | 来源 URL、发布者、更新频率、授权与限制、替代来源 | 不能仅凭搜索摘要判定可信 |
| 数据核验 Agent | 抽查观测、日期、单位、历史合并和来源差异 | 逐项证据表与异常列表 | 不将多个转载视为独立证据 |
| 研究方法 Agent | 将假设转成可计算变量，检查前视与伪相关 | 公式、样本规则、反例、验证设计 | 不把同期相关写成预测或因果 |
| 实现 Agent | 按确定口径实现采集、计算、交互与工作流 | 小范围改动及验证记录 | 不擅自修改指标定义 |
| UI / QA Agent | 检查单位、日期、缺失、响应式和错误状态 | 截图、复现步骤与问题清单 | 页面好看不代表数据正确 |

根据任务规模合并角色；没有真实调用独立 Agent 时不写“多 Agent 已验证”。

## 一个新增指标怎样进入产品

研究问题 → 来源调查 → 主负责人确定口径 → 数据核验者独立回查 → 实现来源适配与计算 → UI 呈现 → 异常场景检查 → 负责人发布验收。

新增、替换或改口径时，记录：指标 ID、原始机构、实际接口、链接、单位、频率、时区 / 收盘规则、观测日期、检查日期、历史起止、缺失处理、复核人和未解决项。差异未解决时保留标记或暂停该来源，不让 Agent 自动编出数值。

## 自动更新与每日巡检

- 每两小时：Actions 调用 `scripts/refresh-public.mjs`，标准化并合并历史，构建发布页面。
- 每日使用时：检查任务记录、各来源最近成功检查与最新观测、是否在休市日、是否保留旧值、是否出现异常跳变。巡检可由负责人调用 Agent 辅助，目前不宣称已有独立自动巡检 Agent 服务。
- 故障处理：定位请求、解析、口径或部署阶段；先保留可用快照，再修适配器并抽样核对；未经授权不修改付费服务、密钥或生产设置。
- 不把定时任务 exit code 为零当成所有来源新鲜或研究结论成立。
