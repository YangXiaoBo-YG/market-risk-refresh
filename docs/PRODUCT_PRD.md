# 市场风险观察站：产品设计与研究方法

## 定位与负责人

产品负责人：YangXiaoBo-YG。由项目负责人提出研究需求、选择指标、定义来源口径与交互方式，组织 AI / Agent 辅助调查、复核和实现，并对发布内容及验收负责。代码和文档通过人机协作完成；不把 AI 辅助实现表述成全部独立手写。

产品定位：面向个人金融与 AI 产业研究，将分散信息转化为可以对照、追溯和持续更新的交互观察工具。主要使用场景是日常研究与假设探索，而非自动交易或投资建议。

## 用户路径与 UI 取舍

进入页面 → 查看风险总览和来源日期 → 选择专题 → 设定日期区间与比较方式 → 悬停读取同日指标 → 回查原始来源。

- 用专题面板和统一日期控件减少切换多个网页的成本。
- MOVE 与股指回撤采用独立纵轴、共用日期；双轴交叉不解释为数值相等。
- 回撤高点取此前全部可用历史，不随可视区间重置，避免换个起点就改变历史风险印象。
- 将窗口不足、缺失值和稀疏披露保留在界面中，不生成看似完整的连续每日数据。
- 网页刷新读取已发布快照，不伪装成实时触发云端采集。

## 来源选择与更新策略

定义和事实说明优先回到原始机构：如 ICE 指标定义、Cboe 波动率资料、美国财政部利率、SEC 与公司披露。实际可获取的价格序列可能来自第三方接口，需同时保留数据供应方和指标原始机构，不能把第三方接口称为官方直连。

新增来源时评估：发布者是谁、口径是否可解释、观测日期和更新频率是否明确、可否稳定访问、能否与另一来源或原文交叉核验、是否允许预期的使用方式。搜索排名不能作为可靠性判断。

当前 GitHub Actions 每两小时检查来源；这不是每两小时必然产生新观测。市场日度数据、公司稀疏披露和网页价格更新频率不同。采集完成、数据新鲜度、部署成功分别验收，不互相替代。

## 错误控制与责任

| 情况 | 当前已有 | 待补 / 操作规范 |
|---|---|---|
| 单一来源请求失败 | 来源隔离、错误记录、保留历史 | 核对 stale 状态是否足够醒目 |
| 历史混合与重复日期 | 日期标准化与历史合并 | 记录来源修订，建立异常值抽查清单 |
| 图形造成错误比较 | 单位与方法说明、窗口不足留空 | 对新图表做研究口径与 UI 双重复核 |
| 定时任务成功但数据没更新 | Actions 与快照可追溯 | 检查各来源 lastSuccess、最新观测和变动条数 |
| 研究结果被过度解释 | 背离模块明确为同期描述 | 不写预测准确率，不以视觉相关替代检验 |

## 验收与迭代

产品负责人负责验收：抽查来源 / 日期 / 数值一致性；同一区间变更展示模式后口径一致；失败时不丢历史；手机和桌面阅读清楚；来源失败与无新观测可区分。

代码级验证采用 TypeScript 检查和生产构建；研究级验证见 [MOVE × SPX 研究说明](RESEARCH_MOVE_SPX.md)。本次文档整理未执行收费 API、重新采集数据或宣称新增统计结论。
